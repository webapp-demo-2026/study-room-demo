# แผนทดสอบ Usability — ระบบจองห้องติวของคณะ (Prototype ใน Figma)

> ไฟล์นี้มี 2 ส่วน: (ก) แผนทดสอบ สถานการณ์งาน ใบบันทึก และแนวให้คะแนน ซึ่งใช้ได้จริง
> (ข) "ตัวอย่างวิธีกรอก" ที่ท้ายไฟล์ — ==ไม่ใช่ผลจากผู้ใช้จริง== ใช้แสดงรูปแบบการกรอกเท่านั้น งานของนักศึกษาต้องกรอกจากการทดสอบกับผู้ใช้จริง 3 คน

## 1. แผนทดสอบ
| หัวข้อ | รายละเอียด |
|---|---|
| เป้าหมาย | หาปัญหาการใช้งานของเส้นทางจองและยกเลิกห้อง (S-01–S-05) เพื่อแก้ Prototype ก่อนเขียนโค้ด |
| ชนิดการทดสอบ | เชิงคุณภาพเพื่อหาปัญหาไปแก้ (formative) ทีละคน ผู้ทดสอบพูดสิ่งที่คิดออกมาขณะทำ (Think-aloud) |
| ผู้ทดสอบ | นักศึกษา 3 คน (P1–P3) ที่เคยนัดเพื่อนติวและไม่ได้อยู่ในกลุ่มที่ทำโครงงาน — 3 คนเป็นขั้นต่ำในห้องเรียน ผลใช้หาปัญหาที่แก้ได้ ไม่ใช่ยืนยันว่าระบบใช้งานง่ายสำหรับผู้ใช้ทั้งหมด |
| สิ่งที่ใช้ | ลิงก์ Prototype ของ Figma (โหมด Present) บนมือถือของผู้ทดสอบหรือ Device ขนาดมือถือ, ใบบันทึก, นาฬิกาจับเวลา |
| บทบาทในทีม | ผู้ดำเนินการ 1 คน (อ่านสถานการณ์ ไม่ช่วย ไม่ชี้), ผู้จดบันทึก 1 คน |
| เวลา | คนละประมาณ 15 นาที: แนะนำ 2 นาที, สถานการณ์ 3 ข้อ, ถามความเห็น 3 นาที |
| ความเป็นส่วนตัว | ใช้รหัส P1–P3 แทนชื่อ ไม่บันทึกเสียง ภาพ หรือคลิปของผู้ทดสอบ ไม่เก็บเบอร์หรืออีเมลไว้ใน Repository; บอกผู้ทดสอบก่อนเริ่มว่าเราทดสอบระบบ ไม่ได้ทดสอบตัวเขา |
| ตัววัด | ทำสำเร็จหรือไม่ (สำเร็จเอง / สำเร็จหลังลองผิด / ไม่สำเร็จ), เวลาที่ใช้, ข้อผิดพลาดที่เห็น, คำพูดสำคัญ |

## 2. สถานการณ์งาน (Task Scenario)
| รหัส | สถานการณ์ที่อ่านให้ผู้ทดสอบฟัง | ทดสอบ | สำเร็จเมื่อ | เวลาเป้าหมาย |
|---|---|---|---|---|
| T-01 | "คุณกับเพื่อนอีก 3 คนจะติววันพฤหัสบดีที่ 3 ธันวาคม บ่ายโมงถึงบ่ายสาม ลองหาห้องและจองให้กลุ่ม" | US-02, US-03 / S-01, S-02, S-03, S-04 / NFR-03 | ถึงหน้า S-04 ด้วยห้องที่จุ 4 คนขึ้นไป | ไม่เกิน 3 นาที |
| T-02 | "กลุ่มเลื่อนนัด คุณไม่ต้องใช้ห้องที่เพิ่งจองแล้ว ลองคืนห้องนั้น" | US-05 / S-05 | กดยืนยันการยกเลิกของการจอง BK-0001 | ไม่เกิน 1 นาที |
| T-03 | "คุณกดยืนยันห้อง A แล้วระบบบอกว่าห้องเพิ่งถูกจอง ลองหาทางจองห้องอื่นในเวลาเดิม" | US-03 (Extension 7a ของ UC-02) / S-03 → S-02 | กลับไปหน้าค้นหาและจองห้อง C ได้ | ไม่เกิน 2 นาที |

สำหรับ T-03 ใน Prototype ต้องมี Frame ข้อความ "ห้องนี้เพิ่งถูกจองในช่วงเวลานี้" ที่ต่อจากปุ่มยืนยันของห้อง A

## 4. ตารางสรุปปัญหา (กรอกหลังทดสอบครบ 3 คน)
| ปัญหา | พบที่ T / S | พบกี่คนจาก 3 | Heuristic ที่เกี่ยวข้อง | ความรุนแรง 0–4 | สิ่งที่จะแก้ใน Prototype |
|---|---|---|---|---|---|
ระดับความรุนแรงตาม Nielsen: 0 = ไม่ใช่ปัญหา, 1 = ด้านความสวยงามเท่านั้น, 2 = ปัญหาเล็ก, 3 = ปัญหาใหญ่ควรแก้ก่อน, 4 = ร้ายแรงต้องแก้ก่อนเปิดใช้ — พิจารณาจากความถี่ ผลกระทบ และการเกิดซ้ำ

## 5. แนวให้คะแนน (สำหรับผู้สอน)
- แผนมีเป้าหมาย ผู้ทดสอบ 3 คนที่ไม่ใช่สมาชิกกลุ่ม และสถานการณ์ 3 ข้อที่เป็นงานจริง ไม่บอกวิธีกด (เช่น ไม่เขียนว่า "กดปุ่มค้นหา")
- ทุกสถานการณ์มีรหัส T-xx ที่โยงกับ US-xx และ S-xx ที่มีอยู่จริงในงานของกลุ่ม
- ตารางผลมีข้อมูลของ P1–P3 ครบทุกช่อง ปัญหาแต่ละข้อโยง Heuristic และระดับความรุนแรงพร้อมเหตุผลสั้น ๆ
- สิ่งที่แก้ระบุ Frame S-xx ที่เปลี่ยน และมีภาพก่อน/หลังอย่างน้อย 1 จุด
