## UC-02 จองห้องติว
| หัวข้อ | รายละเอียด |
|---|---|
| Actor หลัก | นักศึกษา (ผู้จอง) |
| เป้าหมาย | ได้ห้องติวที่จุคนพอในช่วงเวลาที่ต้องการ และทุกคนในกลุ่มได้รับการยืนยัน |
| Precondition | ผู้จองเข้าสู่ระบบแล้ว (FR-01); มีห้องที่เปิดใช้อย่างน้อย 1 ห้อง |
| Main Success Scenario | 1. ผู้จองใส่วันที่ เวลาเริ่ม เวลาสิ้นสุด และจำนวนคน 2. ระบบค้นหาห้องว่าง (include UC-01) และแสดงรายการห้องพร้อมความจุ 3. ผู้จองเลือกห้อง 4. ระบบแสดงหน้าสรุป ห้อง วัน เวลา 5. ผู้จองกด "ยืนยันการจอง" 6. ระบบตรวจกฎ 1–3 ชั่วโมง เวลาเปิด และไม่เกิน 7 วันล่วงหน้า 7. ระบบตรวจว่าไม่มีการจองซ้อนแล้วบันทึกการจอง 8. ระบบแสดงหน้าจองสำเร็จพร้อมรหัสการจอง 9. ระบบส่งอีเมลยืนยันถึงผู้จองและผู้ร่วมจอง |
| Extensions | 2a. ไม่มีห้องว่าง: ระบบแสดง "ไม่มีห้องว่างในช่วงนี้" และให้แก้เงื่อนไข กลับไปขั้น 1; 4a. ผู้จองต้องการเพิ่มเพื่อน: ทำ UC-03 แล้วกลับมาขั้น 4; 6a. ผิดกฎเวลา: ระบบบอกกฎข้อที่ผิด กลับไปขั้น 1; 7a. มีคนจองช่วงเดียวกันไปก่อนระหว่างที่ผู้จองดูหน้าสรุป: ระบบแจ้ง "ห้องนี้เพิ่งถูกจองในช่วงเวลานี้" ไม่บันทึก แล้วกลับไปขั้น 2; 9a. ส่งอีเมลไม่สำเร็จ: การจองยังสำเร็จ ระบบลองส่งใหม่และหน้า "การจองของฉัน" ยังแสดงการจองนี้ |
| Postcondition | มีการจองใหม่ 1 รายการ (และรายชื่อผู้ร่วมจองถ้ามี) ที่ไม่ซ้อนกับการจองอื่นในห้องนั้น; ผู้ที่เกี่ยวข้องได้อีเมลยืนยันหรือระบบตั้งส่งใหม่ |

## UC-04 ยกเลิกการจอง
| หัวข้อ | รายละเอียด |
|---|---|
| Actor หลัก | นักศึกษา (ผู้จอง) |
| เป้าหมาย | คืนห้องเมื่อกลุ่มเลื่อนนัด เพื่อให้คนอื่นจองต่อได้ |
| Precondition | ผู้จองเข้าสู่ระบบแล้ว และมีการจองที่ยังไม่เริ่มอย่างน้อย 1 รายการ |
| Main Success Scenario | 1. ผู้จองเปิดหน้า "การจองของฉัน" 2. ระบบแสดงการจองที่ยังไม่เริ่มเรียงตามเวลา 3. ผู้จองกด "ยกเลิก" ที่การจองที่ต้องการ 4. ระบบแสดงกล่องยืนยันพร้อมห้อง วัน เวลา 5. ผู้จองกดยืนยัน 6. ระบบตรวจว่าเหลือเวลาก่อนเริ่มอย่างน้อย 1 ชั่วโมง 7. ระบบเปลี่ยนสถานะการจองเป็นยกเลิก และห้องกลับเป็นว่างในช่วงนั้น 8. ระบบส่งอีเมลแจ้งการยกเลิกถึงผู้ร่วมจอง |
| Extensions | 5a. ผู้จองกด "ไม่ยกเลิก": กลับไปขั้น 2 ไม่มีอะไรเปลี่ยน; 6a. เหลือน้อยกว่า 1 ชั่วโมง: ระบบแจ้งว่ายกเลิกเองไม่ได้ ให้ติดต่อเจ้าหน้าที่ (UC-06); 3a. ผู้ร่วมจองที่ไม่ใช่ผู้จองไม่เห็นปุ่มยกเลิก (NFR-02) |
| Postcondition | การจองมีสถานะยกเลิก ช่วงเวลานั้นค้นหาเจอเป็นห้องว่าง ผู้ร่วมจองได้อีเมลแจ้ง |

## UC-06 ดูตารางและยกเลิกแทน
| หัวข้อ | รายละเอียด |
|---|---|
| Actor หลัก | เจ้าหน้าที่ดูแลห้อง |
| เป้าหมาย | เห็นการใช้ห้องทั้งวัน และยกเลิกการจองเมื่อคณะต้องใช้ห้องหรือห้องมีปัญหา |
| Precondition | เจ้าหน้าที่เข้าสู่ระบบด้วยบัญชีบทบาทเจ้าหน้าที่ |
| Main Success Scenario | 1. เจ้าหน้าที่เลือกวันที่ 2. ระบบแสดงตารางของทุกห้อง แถว = ห้อง คอลัมน์ = ชั่วโมง 08:00–20:00 3. เจ้าหน้าที่เลือกการจองที่ต้องยกเลิก 4. ระบบแสดงรายละเอียดและช่องเหตุผล 5. เจ้าหน้าที่พิมพ์เหตุผลแล้วกดยืนยัน 6. ระบบเปลี่ยนสถานะเป็นยกเลิกพร้อมเหตุผล 7. ระบบส่งอีเมลแจ้งผู้จองและผู้ร่วมจองพร้อมเหตุผล |
| Extensions | 5a. ไม่ใส่เหตุผล: ระบบไม่ให้ยืนยันและบอกว่าต้องมีเหตุผล; 2a. วันที่ไม่มีการจอง: ระบบแสดงตารางว่างพร้อมข้อความ "ยังไม่มีการจองในวันนี้" |
| Postcondition | การจองที่เลือกมีสถานะยกเลิกพร้อมเหตุผล ผู้เกี่ยวข้องได้อีเมล ตารางแสดงช่วงนั้นเป็นว่าง |
