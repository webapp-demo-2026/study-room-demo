# Persona — ระบบจองห้องติวของคณะ (โครงงานอ้างอิงของเฉลย)

> ตัวอย่างประกอบ ไม่ใช่ข้อมูลจากผู้ให้สัมภาษณ์จริง: บันทึกสัมภาษณ์ P1–P3 และ Persona ในไฟล์นี้เขียนขึ้นเพื่อแสดงวิธีทำและรูปแบบที่ต้องส่ง
> งานของนักศึกษาต้องมาจากการสัมภาษณ์ผู้ใช้เป้าหมายจริงอย่างน้อย 3 คน

## 1. คำถามสัมภาษณ์ (ใช้กับผู้ให้สัมภาษณ์ทุกคน ประมาณ 15 นาทีต่อคน)
ก่อนเริ่ม: บอกจุดประสงค์ ขออนุญาตจดบันทึก (ไม่บันทึกเสียงหรือภาพ) และบอกว่าจะใช้รหัส P1–P3 แทนชื่อ

| ข้อ | คำถาม (ปลายเปิด ไม่ชี้นำ) |
|---|---|
| Q1 | ครั้งล่าสุดที่คุณนัดเพื่อนติวหนังสือ เล่าให้ฟังตั้งแต่เริ่มนัดจนได้ที่นั่งติว |
| Q2 | ตอนหาที่ติว คุณดูหรือถามจากที่ไหนบ้าง |
| Q3 | เคยมีครั้งไหนที่ไปถึงแล้วไม่มีที่ติว เกิดอะไรขึ้น แล้วคุณทำอย่างไรต่อ |
| Q4 | คุณบอกเพื่อนในกลุ่มอย่างไรว่าได้ห้องไหน เวลาเท่าไร |
| Q5 | ถ้ากลุ่มเลื่อนนัด คุณทำอย่างไรกับที่ที่จองหรือนั่งไว้ |
| Q6 | (เจ้าหน้าที่) ทุกวันนี้คุณรู้ได้อย่างไรว่าห้องไหนถูกใช้ เวลาไหน และใครใช้ |

## 2. บันทึกสัมภาษณ์ย่อ (ตัวอย่างประกอบ — ตัดข้อมูลระบุตัวตนแล้ว)
| รหัส | บริบท | ใจความที่ได้ |
|---|---|---|
| P1 | นักศึกษาปี 2 นัดติวกับเพื่อน 4–5 คนสัปดาห์ละ 2 ครั้ง | เดินไปดูหน้าห้องเองว่ามีคนใช้ไหม 2 ใน 3 ครั้งล่าสุดห้องเต็ม ต้องย้ายไปนั่งโรงอาหาร; ส่งชื่อห้องในแชตกลุ่มแต่เพื่อนจำเวลาผิด |
| P2 | นักศึกษาปี 3 ใช้มือถือเป็นหลัก ระหว่างเรียนมีเวลาว่างช่วงสั้น | อยากรู้ห้องว่าง "ตอนนี้" จากมือถือในเวลาไม่ถึงนาที; เคยจองห้องผ่านใบลงชื่อหน้าห้องแล้วกลุ่มเลื่อนนัด แต่ลบชื่อไม่ได้ ห้องจึงว่างทั้งที่มีชื่อจอง |
| P3 | เจ้าหน้าที่ดูแลห้อง 6 ห้องของคณะ | ใช้ใบลงชื่อกระดาษรายวัน ต้องเดินตรวจ; มีห้องปิดซ่อมแอร์แต่นักศึกษาไม่รู้จึงมาเก้อ; อยากเห็นตารางทั้งวันในหน้าเดียวและยกเลิกการจองเมื่อมีกิจกรรมของคณะ |

## 3. จัดกลุ่มสิ่งที่พบ (Affinity) → เป้าหมาย พฤติกรรม ปัญหา
| กลุ่มสิ่งที่พบ | มาจาก | สรุปเป็น |
|---|---|---|
| ต้องเดินไปดูห้องเอง / ไปถึงแล้วเต็ม | P1, P2 | ปัญหา: ไม่รู้สถานะห้องล่วงหน้า |
| ใช้มือถือในเวลาว่างสั้น ๆ | P2 | พฤติกรรม: ทำงานจากมือถือ ต้องการขั้นตอนสั้น |
| บอกเพื่อนผิดเวลา / เพื่อนจำผิด | P1 | เป้าหมาย: ทั้งกลุ่มรู้ห้องและเวลาเดียวกัน |
| ยกเลิกไม่ได้ ห้องว่างเปล่า | P2, P3 | ปัญหา: การจองที่ไม่ใช้แล้วไม่ถูกคืน |
| ห้องปิดซ่อมแต่ไม่มีใครรู้ / ต้องเห็นตารางทั้งวัน | P3 | เป้าหมายของเจ้าหน้าที่: ประกาศและดูแลตารางได้จากที่เดียว |

## 4. Persona หลัก: "แพรวา" นักศึกษาปี 2 ผู้นัดกลุ่มติว
| หัวข้อ | รายละเอียด |
|---|---|
| ภาพรวม | นักศึกษาปี 2 อายุ 19 ปี เป็นคนนัดเพื่อน 4 คนติวก่อนสอบ สัปดาห์ละ 2 ครั้ง ใช้มือถือเป็นหลัก |
| เป้าหมาย | ได้ห้องติวที่จุคนพอในเวลาที่นัด และเพื่อนทุกคนรู้ห้องกับเวลาเดียวกัน |
| พฤติกรรม | เช็กเรื่องต่าง ๆ จากมือถือระหว่างคาบเรียน มีเวลาครั้งละไม่กี่นาที นัดเพื่อนในแชตกลุ่ม |
| ปัญหา | ไปถึงแล้วห้องเต็ม, ต้องส่งรายละเอียดซ้ำให้เพื่อน, เลื่อนนัดแล้วคืนห้องไม่ได้ |
| สิ่งที่ระบบต้องให้ | เห็นห้องว่างตามวัน เวลา จำนวนคนในหน้าเดียว, จองเสร็จในไม่กี่ขั้น, เพื่อนที่ถูกเพิ่มได้อีเมลยืนยัน, ยกเลิกเองได้ |
| ที่มา | P1, P2 (บันทึกตัวอย่างข้อ 2) |

## 5. Persona รอง: "พี่อร" เจ้าหน้าที่ดูแลห้องของคณะ
| หัวข้อ | รายละเอียด |
|---|---|
| ภาพรวม | เจ้าหน้าที่สำนักงานคณะ ดูแลห้องติว 6 ห้องร่วมกับงานอื่น ใช้คอมพิวเตอร์ที่โต๊ะทำงาน |
| เป้าหมาย | รู้ว่าห้องไหนถูกจองเวลาไหนในหน้าเดียว และแจ้งนักศึกษาได้ทันทีเมื่อห้องปิด |
| ปัญหา | ใบลงชื่อกระดาษ ต้องเดินตรวจ, นักศึกษามาเก้อเพราะไม่รู้ว่าห้องปิด |
| สิ่งที่ระบบต้องให้ | ตารางการจองรายวันของทุกห้อง, ปิดใช้ห้องชั่วคราว, ยกเลิกการจองพร้อมเหตุผลและแจ้งผู้จอง, ลงประกาศ |
| ที่มา | P3 (บันทึกตัวอย่างข้อ 2) |

## 6. การตัดสินใจออกแบบที่มาจาก Persona
| การตัดสินใจ | มาจาก | โยงไป |
|---|---|---|
| หน้าแรกหลังเข้าสู่ระบบคือหน้าค้นหาห้องว่าง ออกแบบสำหรับจอมือถือก่อน | แพรวา: ใช้มือถือ เวลาสั้น | US-02, S-02, NFR-04 |
| ใส่จำนวนคนในเงื่อนไขค้นหา และแสดงความจุทุกห้อง | แพรวา: กลุ่ม 4–5 คน | FR-02, US-02 |
| อีเมลยืนยันส่งถึงผู้ร่วมจองทุกคน | แพรวา: เพื่อนจำเวลาผิด | FR-05, FR-06, US-06 |
| ปุ่มยกเลิกอยู่ในหน้า "การจองของฉัน" | P2: คืนห้องไม่ได้ | FR-07, US-05, S-05 |
| ตารางรายวันและประกาศสำหรับเจ้าหน้าที่ | พี่อร | FR-09, FR-10, US-09, US-10 |
